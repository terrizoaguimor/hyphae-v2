# Hyphae v0.2 — performance baseline (commodity hardware)

First-run baseline per ADR-0015. Numbers are measurement, not
contract. No threshold gates per the ADR-0008 + ADR-0015
discipline.

## Methodology

- Hardware: laptop (macOS / darwin 25.4.0).
- Bench harness: `crates/hyphae-bench/benches/substrate_ops.rs`.
- Single-threaded. Sample size 30, measurement time 3s.
- Substrate state shared across iterations within a bench;
  population grows by `iter_count` past the nominal N. See
  ADR-0015 §"Shared substrate, not per-iteration" for the
  caveat.
- Reproducible: `cargo bench -p hyphae-bench --bench substrate_ops`.

## Correction to commit `e440aba`

The commit message for `e440aba` (ADR-0015 harness landing)
incorrectly labelled the first-run numbers as **dev profile**.
They were in fact **bench profile** numbers (the default when
running `cargo bench`).

`Cargo.toml` declares `[profile.bench] inherits = "release"`,
which means `cargo bench` builds with the release optimisation
pipeline plus debug symbols. The build log proves it:

```
Finished `bench` profile [optimized + debuginfo] target(s) in …
```

This file records both profiles for honest comparison.

## Median latency by profile

### `compose` — `SurfaceRealizer::realize`

| Working set size | DEV profile | BENCH profile | Speedup |
|---|---|---|---|
| 1 fragment | 3.80 μs | 559 ns | **6.8×** |
| 3 fragments | 17.0 μs | 2.13 μs | **8.0×** |
| 7 fragments | 43.9 μs | 5.50 μs | **8.0×** |

Compose is pure CPU — string formatting, lexicon lookup, shape
walking. The release pipeline's inlining + vectorisation produces
a clean ~8× speedup. At 5.5 μs per 7-fragment compose, the
realizer is **not a bottleneck** anywhere in the v0.2 surface.

### `ingest` — `Substrate::ingest`

Encoding fan-out: `InputGate → Episodic + Valence → Reward`.
Each call writes one journal entry, runs ethics evaluation,
updates the conductivity graph + temporal context.

| N stored | DEV profile | BENCH profile | Speedup |
|---|---|---|---|
| 10 | 11.0 ms | 8.73 ms | 1.26× |
| 100 | 12.4 ms | 8.83 ms | 1.41× |
| 1000 | 13.1 ms | 9.62 ms | 1.36× |

Ingest is **I/O bound**: SHA-256 hash computation, `fjall`
journal append, `redb` state writes, ethics audit. The release
profile helps the SHA-256 path (~1.3-1.4× total) but cannot
optimise the disk syncs. At 9.62 ms per ingest at N=1000, the
ceiling is the journal flush, not the cognition path. This is
exactly the trade-off ADR-0003 priorities: audit non-negotiable.

### `recall` — `Substrate::recall_signal`

Ethics evaluation at `CoveragePoint::Recall`, embed the cue,
`pattern_complete` over stored fragments (cosine similarity),
cascade activation, route emissions.

| N stored | DEV profile | BENCH profile | Speedup |
|---|---|---|---|
| 10 | 4.27 ms | 3.98 ms | 1.07× |
| 100 | 5.95 ms | 4.13 ms | 1.44× |
| 1000 | 11.2 ms | 6.31 ms | **1.77×** |

Recall's cosine pattern_complete is a hot inner loop —
`O(N × D)` where D = embedding dimension. At N=1000 the release
profile vectorises the inner accumulator and gives a meaningful
1.77× speedup. As N grows further, the gap should widen.

## What the numbers say

- **Compose is free.** Sub-microsecond per fragment in release.
  Surface realizer complexity is not a v0.2 concern.
- **Ingest is dominated by audit.** The non-negotiable journal +
  ethics commitments cost ~9 ms per ingest. The architecture's
  choice (ADR-0003: ethics RADAR, hash-chained journal) is the
  observed bottleneck — which is the correct bottleneck.
- **Recall scales gracefully to 1000 fragments.** 6.3 ms at
  N=1000 means the v0.2 substrate handles small-to-mid memory
  ranges (low thousands of fragments) within the
  conversational-latency budget (< 100 ms for a full turn).
- **Release matters more for retrieval than for ingest.** This
  inverts the usual heuristic. The reason is concrete: ingest is
  I/O bound, recall has a pure-CPU hot loop.

## Honest caveats

1. **Single laptop.** A different machine produces different
   numbers. The pattern (compose << recall < ingest, recall
   scales worse than ingest with N) should generalise; absolute
   numbers will not.
2. **Shared-substrate measurement drift.** Each iteration adds a
   fragment. After ~500 iterations the substrate carries
   `N + 500` fragments. The headline number is "ingest near N",
   not "ingest at exactly N".
3. **Tempdir is likely tmpfs-backed on macOS.** Persistent-disk
   measurements would be slower. A future ADR can pin to a real
   FS for the disk-bound axis.
4. **No multi-thread scaling measurement.** Single-threaded
   only. Concurrent operation latency may diverge.
5. **The release profile carries debug symbols** (`debug = true`
   in `[profile.bench]`). A pure release build (no debug)
   might be marginally faster.

## Reproducibility

```bash
# Release/bench profile (default)
cargo bench -p hyphae-bench --bench substrate_ops

# Dev profile (for comparison)
cargo bench -p hyphae-bench --bench substrate_ops --profile=dev

# Reduced run (shorter wall time, less stable stats)
cargo bench -p hyphae-bench --bench substrate_ops \
    -- --sample-size 30 --measurement-time 3

# Single bench group
cargo bench -p hyphae-bench --bench substrate_ops compose
```

HTML reports under `target/criterion/<bench_name>/report/`
(gitignored).
